RemoteCode · Token Saver

Economizar o máximo de tokens possível — sem degradar Claude e Codex

Auditoria do que o RemoteCode já faz hoje para reduzir tokens nas LLMs caras, mais um plano priorizado de novas economias. Princípio: fail-open, reversível, e medido no ledger real — nunca “economia estimada de marketing”.

01 Objetivo e restrições

Maximizar tokens economizados nas sessões Claude/Codex mantendo a mesma qualidade de raciocínio e de resultado final.

Sucesso =

  • Mais tokens medidos no ledger local (distill stats).
  • Sem aumento de retrieve-rate patológica (modelo pedindo original o tempo todo).
  • Sem regressão em tarefas de código (edits, testes, diffs, paths, erros).
  • Fail-open: sidecar down → provider continua com input original.

Restrições duras (já no AGENTS.md)

  • Sem reverse-proxy reescrevendo HTTP do provider (envenena prompt/KV cache).
  • Sem ONNX Runtime C++ sem decisão explícita de licença/benchmark.
  • Core ML / MLX como caminho nativo padrão.
  • Lossy só com original em [[rc:<handle>]] recuperável.
  • Claims de savings só do ledger / usage real, não de contagem de chars “solta”.

02 Como o RemoteCode economiza tokens hoje

O Token Saver é um caminho local, pago, que roda no Mac. Ele ataca input (prompts, tool output) e, via linguagem Distill, também output do agente.

2.1 Componentes

2.2 Modelos locais aprovados

  • E4B (distill-E4B-it-4-bit-MLX) — preferido em hosts com ≥16 GiB memória unificada.
  • 1.7B (distill-1.7B-4bit-MLX) — fallback / máquinas menores.
  • Encoder embeddings (BERT-style) para ranking/extração — licenças permissivas pinadas no manifest.

03 Pipeline de um turno (visão operacional)

Dois eixos de economia: o que entra no modelo caro e o quanto o modelo caro escreve de volta.

Entrada (input tokens) — maior alavanca

1
Skill / instruções Distill
Agente instruído a pipar saída e falar compacto. Prefixo de instrução estável (cache-friendly via session-learn region).
2
Tool roda
Claude: PostToolUse hook. Codex: wrappers transparentes no PATH (rg, cat, git…).
3
Router determinístico
JSON minify/CSV, log collapse, build/search runs, etc. — zero GPU quando suficiente.
4
Encoder BERT (query-aware)
Seleciona linhas relevantes em logs grandes (≥24 linhas, ≥2k chars) sem chamar LLM local.
5
Fallback / MLX
Só se necessário e permitido pela lane. Fail-open se deadline/queue/erro.
6
Gates de qualidade
LiteralPreservation, Faithfulness, min-gain, net-positive. Rejeita → original.
7
Marker + ledger
[[rc:handle]] + registro de savings honestos (cache_state consciente).

Saída (output tokens) — segunda alavanca

A
Linguagem Distill (SR1)
Agente responde em átomos curtos (S/C/D…). Isso reduz tokens de saída cobrados pelo provider.
B
SR1 humanize (local)
UI humaniza para o usuário; o provider já recebeu/emitiu o compacto. Savings creditados com fator de expansão de transcript.
C
Handles limpos
Mensagens finais stripam handles não resolvidos antes de persistir para o usuário.
Warm resume (NetPositiveGate): prompts < 2 000 chars ou follow-ups em < 300s não passam pelo compressor de prompt — evita latência MLX em trocas rápidas. Deterministic pre-passes (dedupe de blocos, diff window) ainda podem aplicar.

Regra de ouro: economizar tokens no tool output e em re-reads costuma valer 5–20× mais do que comprimir o texto curto do usuário — e com menos risco de mudar a intenção.

06 Propostas para economizar ainda mais

Ordenadas por ROI de tokens salvos ÷ risco de qualidade. Cada item deve preservar Claude/Codex “full quality” no raciocínio; o trabalho barato fica no Mac.

P0 Wins rápidos, baixo risco, alto volume

P0.1 — Expandir wraps transparentes (Codex parity + mais comandos ruidosos)

Problema: Codex depende de wrappers; o catálogo é curto. Saídas de npm, pnpm, yarn, cargo, pytest, go test, docker, kubectl, terraform, bun, node (não TUI) ainda escapam se o agente não pipar.

Proposta: ampliar WrappedCommandCatalog + regras read-only em CommandWrapPolicy (mesma lógica de subcomandos mutantes). Thresholds agressivos (1 KB / 10 linhas) com handle sempre.

Qualidade: passthrough em mutações; fail-open; contratos de compressão por família (test/build/search).

Impacto: Alto · Risco: baixo · Esforço: M

P0.2 — Element-dropping estruturado SEMPRE com store (diff / test / stack / HTML / skeleton)

Problema: vários crushers lossy excelentes existem, mas o path local default usa allowElementDropping: false. Muito volume estruturado ainda vai para head/tail genérico ou BERT.

Proposta: no sidecar (onde o reversible store já está), default-on para tipos estruturados com handle obrigatório. BERT só se o router não ganhar ≥10% e literais estiverem seguros.

Qualidade: LiteralPreservation + faithfulness; retrieve trivial para expandir.

Impacto: Alto · Risco: baixo · Esforço: M

P0.3 — Subir pipe-hit-rate medido (forçar compressão sem depender de “bom comportamento” do agente)

Problema: o skill manda pipar tudo, mas modelos caros às vezes ignoram. O hook Claude e os wraps resolvem boa parte — o gap é o resto.

Proposta:

  • Instrumentar pipe_hit_rate e “raw large tool outputs that skipped compress”.
  • Para Claude: manter hook universal (já sem allowlist) e reduzir timeout miss (hoje 1 s) com path determinístico síncrono primeiro (sub-ms).
  • Para Codex: PATH wrap + opcional interceptor de shell se o provider permitir.
  • Meta de produto: pipe/hook hit rate ≥ 80% em outputs >1 KB.

Impacto: Alto · Risco: baixo · Esforço: M

P0.4 — Fast-path determinístico no prompt path (sem esperar MLX)

Problema: NetPositiveGate pula compressão em warm resume / <2k. Certo para MLX; errado se o win for 100% determinístico e barato (dedupe, JSON, log).

Proposta: separar gates: always-run deterministic pre-pass (já parcial) + MLX only if cold & large. Abaixar floor só para deterministic (ex.: 400 chars estruturados).

Impacto: Médio-alto · Risco: baixo · Esforço: S

P1 Grande economia em threads longas (ainda sem perder qualidade)

P1.1 — Ativar ReadLifecycleMasker (reads superados → marker + retrieve)

Problema: Read é excluído do hook (correto para edits), mas o mesmo arquivo reaparece no contexto em turns seguintes. Threads longas reenviam kilobytes já vistos.

Proposta: ligar mask com precondições duras:

  • MCP rc_retrieve disponível no turno;
  • manter últimos N turns unmasked (default 2);
  • nunca mask se houve error no read;
  • circuit breaker se retrieve-rate > limiar;
  • ponteiro legível + handle (não opaco sem retrieve).

Qualidade: modelo ainda edita com exact bytes via retrieve; se retrieve falhar, session desliga a lane (já modelado em TokenSaverCircuitBreaker).

Impacto: Alto · Risco: médio · Esforço: L

P1.2 — “File fingerprint + delta” em re-reads

Problema: segundo Read do mesmo path muitas vezes muda pouco (ou nada).

Proposta: store do content hash por path/thread; se hash igual → “unchanged, see [[rc:…]] / block #N”; se mudou → unificado diff compressível (DiffCrusher) em vez do arquivo inteiro.

Impacto: Alto · Risco: médio · Esforço: L

P1.3 — Compactação de transcript / tool history por importância

Problema: contexto cresce com tool noise antigo que já não é decision-relevant.

Proposta: usar DistillImportanceScorer + budget aprendido (TokenSaverTranscriptLearner) para dropar linhas de tool antigas com handle; nunca dropar a última falha / último diff / últimos approvals.

Impacto: Médio-alto · Risco: médio · Esforço: L

P1.4 — Cross-turn near-dup (embeddings) com ponteiros legíveis

Problema: logs “quase iguais” entre turns não batem byte-exact.

Proposta: ativar EmbeddingNearDuplicateNominator + DistillBlockDeduper cross-turn, com Jaccard/embedding alto (≥0.90), same thread, e texto legível do tipo “quase idêntico ao bloco #N (diff: …)”.

Impacto: Médio · Risco: médio · Esforço: M

P2 Output do modelo caro + cache alignment

P2.1 — Distill language enforcement mais forte (sem mudar capacidade)

Problema: skill existe, mas Claude/Codex às vezes “esquecem” e escrevem prosa longa (output tokens caros + transcript maior).

Proposta:

  • Manter skill no system prompt (já feito no Claude bridge).
  • Reforço por provider: reminder curto no final do user turn quando Token Saver on (“reply SR1 only”).
  • Opcional: pós-process local só de display (não reescrever o que o provider já cobrou — output já foi gasto; o win é no próximo input se SR1 for o que entrou no histórico).
  • Completar dsl learn-thread para calibrar maxLines/prefixes por provider a partir de transcripts reais.

Impacto: Médio · Risco: baixo · Esforço: S–M

P2.2 — CacheAligner: estabilizar prefixos e isolar voláteis

Problema: UUIDs, timestamps ISO, JWTs e hex longos no prefixo quebram cache do provider → re-cobrança de system/skill/history.

Proposta: usar CacheAlignerVolatileTokenDetector ativamente:

  • mover tokens voláteis para o sufixo do prompt (segmento não-cacheado);
  • normalizar timestamps de tool noise quando não forem o objeto da pergunta;
  • telemetria de volatile warnings já existe — transformar em ação.

Impacto: Alto em sessões longas com cache · Risco: médio · Esforço: M

P2.3 — Não pagar “prompt compression” em path que o provider já cacheia mal

Continuar proibindo reverse-proxy. Em vez disso: comprimir só o delta do turno (já a filosofia do NetPositiveGate) e garantir que o prefixo estável seja byte-idêntico entre turns (session-learn markers já ajudam).

Impacto: Médio · Risco: baixo · Esforço: S

P3 Novas frentes (maior design, grande upside)

P3.1 — Query-aware file read (skeleton first)

Em vez de mandar o arquivo inteiro no primeiro Read quando a query é “onde está X?”: skeleton (SourceCodeSkeletonizer) + top-k chunks por embedding/query; exact bytes on demand via retrieve. Opt-in por perfil (aggressive) com circuit breaker.

Impacto: Muito alto · Risco: alto se default-on · Esforço: XL

P3.2 — Prose pruning com gates (WebFetch / docs longas)

Ligar allowLossyProsePruning só com: handle + LiteralPreservation + Faithfulness + minGain + netPositive. Shadow mode 1–2 semanas (ShadowEvaluator) antes de default-on.

Impacto: Médio · Risco: médio · Esforço: M

P3.3 — Vision / screenshots

Medir volume real de image tokens; então: downscale, strip EXIF, compressão metadata, OCR local + texto em vez de reenviar imagem em turns seguintes, se a query não exigir pixels.

Impacto: Alto se vision for usado · Risco: médio · Esforço: L

P3.4 — Memória de projeto (CCR scoped) em vez de re-anexar contexto

TokenSaverMemoryStore já modela save/retrieve/search por project/provider/thread. Completar wiring: decisões estáveis (“arquitetura X”) viram handle indexado; o agente referencia em vez de re-colar.

Impacto: Médio-alto · Risco: médio · Esforço: L

P3.5 — Auto-tune de thresholds por projeto

Ledger + route telemetry → subir/baixar minBytes/minLines e agressividade por tipo de repo (monorepo vs app pequeno), com canary e circuit breaker (já esboçado em TokenSaverCircuitBreaker / SeededCorruptionCanary).

Impacto: Médio · Risco: médio · Esforço: L

P3.6 — Structured tool results nativos

Onde o RemoteCode controla a tool surface: forçar JSON schema enxuto (paths, exit code, summary) e só embutir blob raw atrás de handle. Menos dependência de NLP local.

Impacto: Alto · Risco: baixo se opt-in tools · Esforço: XL

08 Guardrails de qualidade (não negociáveis)

“Salvar tokens” que força o modelo caro a errar ou a re-pedir o original custa mais tokens. Estes gates já existem — o plano só exige que novas features passem por eles.

Gates de aceitação de compressão

  • LiteralPreservation — paths, codes, numbers, quotes.
  • Faithfulness / NLI — não inventar; reverse coverage.
  • minGainRatio (≥10%) — senão keep original.
  • NetPositive — dollars/tokens líquidos > 0 (inclui retrieve debit).
  • Handle obrigatório em qualquer elisão.

Circuit breakers (já modelados)

  • retrieve_rate alto → demote pass-through
  • net billed negativo → disable lane
  • encoder thrash / deadline latch → disable encoder
  • canary false-accept / omission → revert aggressive ratios
  • MCP retrieve down → disable masking session-wide
Anti-meta: nunca comprimir Read/Edit/Write de forma que o modelo perca bytes exatos necessários para patch. Compressão de arquivo só com skeleton + retrieve, ou mask de cópias superadas — nunca do “working set” ativo.

09 Como provar que economizou (sem se enganar)

Métricas que importam

  • saved_tokens por provider / mode / route_stage / cache_state
  • pipe_hit_rate e tool_output compressed vs eligible
  • route share: deterministic % · encoder_bert % · llm_mlx % · verbatim %
  • retrieve_rate e masked_retrieve_failure
  • p95 latency do sidecar (não pode estragar UX do turno)
  • billed usage provider (account usage) vs ledger local — coerência de tendência

Gates de claim público

Já codificados em TokenSaverQualityBenchmark:

  • corpus fixo mínimo
  • sem regressão de literais
  • pipe_hit_rate medido presente
  • savings medidos presentes

Nenhuma campanha de “% saved” sem esse gate.

Baseline antes de cada onda

  1. Rodar N sessões representativas (build/test/debug, refactor, web fetch) com Token Saver on/off.
  2. Capturar distill stats + usage provider + contagem de retrieves.
  3. Fixar corpus de qualidade (paths, error codes, diffs, stack traces).
  4. Ship da onda só se: savings ↑ e quality gates estáveis e retrieve_rate não explode.

10 Explicitamente NÃO fazer

  • Proxy HTTP do Claude/Codex reescrevendo bodies — proibido (cache poison + ToS/complexity).
  • Comprimir system prompt de forma diferente a cada turn — destrói prompt cache.
  • Trocar Claude/Codex por modelo barato no path crítico — o objetivo é economizar tokens do modelo caro, não rebaixá-lo.
  • Fail-closed no CLI — já foi bug histórico; nunca voltar.
  • Economia por contagem de caracteres vendida como billing — só ledger/usage.
  • ONNX / Python sidecar / HTTP proxy ad hoc — fora da arquitetura nativa.
  • Compressão de Edit/Write echoes — quebra patches.

Σ Resumo executivo

Já estamos fortes em

  • Arquitetura fail-open + reversible handles
  • Router determinístico + BERT antes de LLM local
  • Hook Claude + wraps Codex + skill Distill
  • Gates de qualidade e circuit breakers desenhados
  • Ledger real de savings

Maior upside ainda não capturado

  1. Mais tool output estruturado esmagado com store (P0)
  2. Mais comandos wrapados no Codex (P0)
  3. Mask/delta de Reads e history em threads longas (P1)
  4. Cache alignment (não re-pagar prefixo) (P2)
  5. Skeleton-first / vision / memory (P3, com flags)
Frase-guia: o Mac (Distill) deve ser o “lixo e ruído”; Claude e Codex devem receber só o que muda a decisão — com bytes exatos a um retrieve de distância. Assim maximizamos tokens salvos sem tirar poder dos modelos caros.
