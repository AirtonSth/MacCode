This checkpoint proves the macOS contextual resolver's actual provider-start path reaches scoped runtime preparation, then refuses model launch and cleans up. It does not enable contextual provider execution. Public router and Bots window gates are unchanged; restricted mode and public contextual provider admission remain unavailable. There is no Mac fallback, and the resolver never returns a guest launch plan for a pinned thread.

## Actual path

`AppContext.coordinator.startRun` enters the real Distill ACP adapter's `openSession`, which invokes the wired Bot guest run resolver. For a pinned thread, that resolver invokes `BotContextGuestResources.prepare` with an injectable raw secret store defaulting to `BotKeychainSecretStore`; this replaces the prior nil-only preparation path. It provisions through the scoped guest service and stages credentials from that bot/context scope plus private configuration/environment. The probe populates only synthetic values. After preparation, the resources are cancelled/stopped and the resolver refuses model launch with the same model-unavailable error. Mandatory provider refusal remains in force; cancellation/revocation failure does not turn this into model admission.

Public routing and Bots window admission gates remain unchanged. A native public send after wipe still rejects and creates no runtime. Pinned threads do not fall through to the legacy Mac session path.
