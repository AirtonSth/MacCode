# Context-scoped resume

## Current implementation

Scoped sessions persist native Distill history under a per-conversation UUID inside the derived bot-by-context storage guest home. Host-only bindings live at `<appSupport>/bot-context-sessions/<storageBotID>/<convUUID>.json`; they are not guest-mounted. Each binding captures the immutable canonical pin, host, bot, context, revision, thread, cwd, parent and native cursor. The actual ACP `session/new` or `session/load` callback records the returned native session ID before the host-thread-started receipt.

Resume validates current grants, scoped key, pin, parent and cwd before host admission or runtime effects. The coordinator supplies the trusted native cursor; callers cannot override it. For a resume, missing or mismatched binding/cursor and lost native home fail closed; no fresh-session fallback is permitted. Retired provider histories and cross-family resumes are refused before effects. An adapter context-preserves-session guard blocks replacement through `session/new`; legacy non-scoped fallback remains unchanged.

Cancellation and startup recovery scrub config and environment credentials and revoke bearer access; required physical stopping is verified before cleanup is recorded as complete. Native history and host binding remain retained. Public UI, router and gateway remain closed. No OAuth refresh, macOS fallback or UI change is included; iOS work is documentation only.
