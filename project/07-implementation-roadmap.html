Implementation Roadmap

Phased plan from empty repo to signed release. Each phase has explicit pass criteria.

Phase 0: Legal And Technical Baseline

WorkPass criteria
Decide cmux license path: GPL-compatible derivative, commercial license, or clean-room behavior clone.Written decision exists before copying any cmux source.
Choose layout dependency: Bonsplit reuse, licensed cmux code, or independent split/tab implementation.Prototype renders split tree with surface tabs.
Choose terminal dependency: libghostty integration or alternative.Terminal proof can run shell, resize, copy/paste, and close cleanly.
Create Swift package/Xcode project skeleton.CI builds app and test target.

Phase 1: Native Shell

WorkPass criteria
AppKit app lifecycle, menu, settings stub, window controller.App opens a native window with no fake chrome.
Workspace sidebar with create/select/rename/close.Workspaces persist across restart.
Pane split tree and surface tab strip.Can create two panes and switch multiple surfaces inside a pane.
Command palette basics.Can run workspace/surface commands by keyboard.

Phase 2: Terminal Surface

WorkPass criteria
Terminal surface host view and shell process.Shell opens in workspace cwd and accepts input.
Focus routing, copy/paste, resize, scrollback.Terminal remains usable after split, tab switch, and window focus changes.
Terminal session snapshot.Quit/reopen restores terminal surface and scrollback best effort.
Terminal socket commands.surface.send_text, surface.send_key, surface.read_text work.

Phase 3: Browser Surface

WorkPass criteria
WKWebView browser surface with address bar.Can open URL, back/forward/reload, split beside terminal.
Browser profile and cookie storage.Profile survives restart and can be cleared.
P0 automation commands.Snapshot, eval, wait, click, fill, type, press, screenshot pass integration tests.
Browser session snapshot.URL and basic history restore.

Phase 4: Persistence And Socket Core

WorkPass criteria
SQLite schema steps and repositories.All domain stores covered by unit tests and schema-step tests.
JSON-RPC socket server and CLI.CLI can drive windows, workspaces, panes, surfaces, notifications, and browser P0.
Event stream.CLI can reconnect and continue after last seen event sequence.
Session snapshot writer/loader.Window/workspace/pane/surface state restores deterministically.

Phase 5: Agent Runtime

WorkPass criteria
Codex Process runner and event parser in Swift.Parser tests cover thread, turn, reasoning, plan, tool, assistant, failure, and cancellation.
Claude Process runner and event parser in Swift.Parser tests cover streaming content blocks, tool use/results, assistant text, result, and errors.
Common normalized event model.Same Agent App timeline renders fixture streams from both providers.
Run supervisor.Stop/restart/app quit never leaves stale running rows.

Phase 6: Agent App Surface

WorkPass criteria
Native thread list, timeline, composer, provider/model controls.Can create thread and send prompt to fake provider.
Codex integration.Real Codex run streams and persists final message.
Claude integration.Real Claude run streams and persists final message.
Agent socket/CLI commands.agent.open, agent.message.send, agent.run.stop, agent.state.current pass.
Agent session restore.Reopen restores selected thread without duplicating active run.

Phase 7: Clean First Run And Fixtures

WorkPass criteria
Clean first-run bootstrap.Production first launch creates only RemoteCode 2-owned directories, schema, settings, and no sample user data.
Generated fixture factory.Tests can generate deterministic projects, Agent App threads, terminal sessions, browser state, event streams, and direct-VPN targets.
Filesystem trace test.Automated proof shows first run does not read or probe previous app paths, exports, or user home data sources.

Phase 8: Polish, QA, Release

WorkPass criteria
Keyboard shortcuts and command palette parity.Core cmux shortcuts work or are documented as changed.
Performance tuning.Meets cold start, memory, scrolling, and streaming budgets.
Signing, notarization, updater, installer.Fresh install and update path pass on clean macOS test user.
Release docs and rollback.Clean first-run behavior, fixture-only test data, known limitations, and recovery path documented.
