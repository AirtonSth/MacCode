Global Definition Of Ready

  • The agent must read 01-product-requirements.html, 03-target-architecture.html, and the card details before editing.
  • The agent must state assumptions and blockers before coding when the card depends on licensing, external tools, signing credentials, or provider behavior.
  • The agent must keep diffs surgical and use Swift-native implementations unless the card explicitly allows a temporary stub.
  • The agent must not copy cmux source unless the license decision card is completed with explicit approval.
  • The agent must use T3 Code as the Agent App and general UI reference: dense developer-tool layout, project/thread sidebar, chat timeline, bottom composer, top action toolbar, diff panel, terminal drawer, command palette, and provider/runtime controls.
  • The agent must not blindly paste TypeScript/React source into Swift. Direct T3 Code source reuse is allowed only when the implementation preserves MIT attribution and the card explicitly asks for source translation; otherwise copy behavior, structure, and UX patterns.
  • The ideal UI stack is fixed unless a later architecture review changes it: SwiftUI for sidebar, chat, composer, lists, settings, and command palette; AppKit for window ownership, responder chain, menus, focus, terminal host, and complex split panes; Liquid Glass only for controls and bars, never the main content canvas.
  • The desktop core must be designed for the future mobile mirror from day zero. The mobile app is not in current build scope, but every command, event, identity, and state boundary must be ready for a future direct app-to-computer client.
  • Remote access architecture is direct only: future mobile connects to the desktop over VPN or trusted local network using desktop-hosted HTTP/WebSocket APIs. No relay, no private backend, no cloud broker, and no server-side repository mirroring.

Future Mobile Direct-VPN Contract

The mobile app is deferred. The desktop core is not deferred: it must be built so a future mobile client can mirror and control the same state without rewriting the foundation.

AreaRemoteCode 2 requirement
Product promiseRemoteCode means the user can later do from mobile what they can do on desktop. Mobile actions must execute on the computer, against the same workspaces, panes, Agent App threads, terminals, browser surfaces, git state, and settings allowed by policy.
TransportExpose a desktop-owned direct HTTP plus WebSocket API intended for VPN or trusted local network access. Do not design any relay/private-backend/cloud-broker path. The desktop is the source of truth and the only machine that touches repositories and provider CLIs.
DiscoveryDesign discovery metadata for server id, app version, capabilities version, auth mode, visible host/port, VPN/LAN connect hints, and health. mDNS, QR pairing, and manual host entry may be supported, but they must resolve to direct desktop addresses only.
Pairing and trustUse explicit pairing, per-device identity, revocable tokens, secure storage, token rotation, and visible device management. Never ship a production default token. Desktop user must opt in before listening beyond loopback.
State mirrorEvery mutating action must flow through a versioned command bus and emit ordered events with sequence, timestamp, request id, origin client id, actor, target ids, and replay rules. UI, CLI, tests, and future mobile must use the same domain actions.
Realtime behaviorWebSocket clients need join/leave semantics, last-sequence replay, ack/idempotency, backpressure handling, reconnect jitter, stale-host recovery, and origin filtering so a mobile-originated command does not duplicate in the desktop UI.
SecurityRemote control is high risk. Bind to loopback by default, require explicit enablement for VPN/LAN, audit sensitive commands, redact secrets, rate-limit auth failures, and make file/terminal/provider access policy-driven.
Scope boundaryDo not build the mobile app in this project phase. Build desktop APIs, contracts, fixtures, and tests that prove the future mobile client can be added without replacing the desktop core.
