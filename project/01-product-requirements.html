Product Requirements

Defines the product contract before implementation. This is intentionally strict: RemoteCode 2 is cmux plus Agent App, not a generic rewrite.

Goal Statement

RemoteCode 2 must be a native Swift macOS application with cmux-style workspaces, panes, terminal surfaces, browser surfaces, socket/CLI automation, notifications, and session restore. It must add an Agent App surface that provides the current RemoteCode graphical Codex/Claude workflow as a first-class tab/split surface.

Hard Requirements

IDRequirementPass criteria
R1Native Swift rewriteNo Electrobun, Electron, Tauri, React runtime, Vite server, or Bun backend in the final desktop app process.
R2cmux-like primitivesApp exposes windows, vertical workspaces, panes, split layout, and surface tabs. Keyboard and command palette map to those primitives.
R3Terminal surfaceUser can open a terminal surface in any pane, send input, resize, split, close, restore scrollback, and receive notifications.
R4Browser surfaceUser can open a browser surface, navigate, split it beside terminal/agent surfaces, and use browser automation commands.
R5Agent App surfaceUser can open an Agent App surface in any pane and run Codex or Claude against the workspace cwd.
R6Provider parityCodex and Claude both support model selection, permission/sandbox controls where supported, running state, streaming events, failure state, stop, and resume.
R7Clean state continuityProjects, threads, messages, provider thread IDs, streaming turn snapshots, workspace selection, terminal snapshots, and browser state persist only after they are created by RemoteCode 2.
R8AutomationSocket/CLI can create workspaces, panes, terminal/browser/agent surfaces, focus surfaces, send input, read state, and automate browser surfaces.
R9Session restoreQuit/reopen restores windows, workspaces, panes, surfaces, browser URLs/history where possible, Agent App thread context, terminal scrollback, and focused surface.
R10PerformanceCold launch and memory use must be materially closer to cmux than to Electron/Electrobun. Performance budgets are defined in the QA plan.

Non-Goals For V1

  • No mobile rewrite in the first desktop release unless explicitly reprioritized.
  • No simulated desktop chrome inside the app. Use native macOS chrome and toolbar behavior.
  • No generic plugin marketplace before the core Agent App surface is stable.
  • No remote cloud VM feature unless cmux parity requires a stubbed API shape.
  • No retention of the React UI as a permanent WKWebView shell. Current local RemoteCode may be studied only as product behavior reference.

Definition Of Done

  • Must ship as a signed native macOS app with installer/update path.
  • Must include clean first-run tooling, generated test fixtures, and filesystem-trace proof that no previous app data path is touched.
  • Must pass unit, integration, socket CLI, UI automation, session restore, and performance gates.
  • Must document any cmux behavior intentionally deferred from V1.
