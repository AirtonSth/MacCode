Release Channels

Stableio.remotecode.RemoteCode2Signed user release.

Packaging Requirements

  • Universal macOS app target: arm64 first; x86_64 support requires a dependency proof report before stable release.
  • Signed app and signed CLI helper.
  • Notarized DMG with app drag target.
  • Updater configured before stable release. Sparkle is the default candidate.
  • App data directories separated by release channel to protect stable data during canary testing.

First-Run Experience

StepBehavior
Dependency checkDetect Codex CLI, Claude CLI, shell, terminal backend, browser profile permissions.
Fresh-start confirmationState that RemoteCode 2 starts from zero and does not read previous app data. Remote access settings remain disabled by default.
Workspace creationAllow opening a folder and choosing initial surface: Agent App, terminal, or browser.
CLI installOffer to install/update remotecode2 CLI symlink in a user-approved location.

Rollback Plan

FailureRollback
Fresh-start data bugDelete the RemoteCode 2 target DB and app support directory for the affected channel. No previous app data is involved.
Bad app releaseUpdater rollback to previous stable. Canary and stable data remain separated.
Provider parser regressionDisable affected provider through feature flag and keep local thread data intact.
Browser automation regressionShip patch release with unsupported command guard instead of broken behavior.

Release Checklist

  • Pass all unit/integration/UI/performance gates.
  • Pass clean first-run filesystem trace and generated fixture suite.
  • Pass clean macOS user install, launch, and first workspace flow.
  • Pass signed CLI socket commands against release app.
  • Pass updater install from previous canary build.
  • Pass notarization validation with spctl and Gatekeeper.
