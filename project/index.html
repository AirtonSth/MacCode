RemoteCode 2 Swift Rewrite Plan

Planning package for /Users/samuelfajreldines/dev/remotecode2/project. Last updated 2026-05-14. Planning only: no product implementation is included.

Target

Build a native Swift macOS app that behaves like cmux and adds one first-class surface type: Agent App. The app keeps cmux primitives: windows, vertical workspaces, panes, split layout, surface tabs, terminal surfaces, browser surfaces, notifications, socket/CLI automation, and session restore. RemoteCode adds an Agent App surface that provides the current RemoteCode graphical Codex/Claude experience inside the same split/tab model.

Definitions

TermMeaning in RemoteCode 2
WindowA native macOS NSWindow containing one workspace stack.
WorkspaceVertical sidebar entry, equivalent to cmux workspace/tab. Owns cwd, metadata, panes, surfaces, and notifications.
PaneA split region inside a workspace.
SurfaceA tab inside a pane. Surface types are terminal, browser, and agentApp for V1.
Agent AppNative Swift graphical chat/thread/workspace UI for running Codex or Claude in a project. It replaces the current Electrobun/React RemoteCode desktop app.

Primary Decisions

DecisionResult
RuntimeNative Swift/AppKit/SwiftUI app. No Electrobun, Electron, or Tauri in the final product.
Layout modelAdopt cmux workspace/pane/surface model. Add agentApp as a new surface type.
TerminalUse cmux-style libghostty integration if licensing permits. Fallback is a Swift terminal component only if libghostty cannot be used.
BrowserUse WKWebView plus cmux-like browser automation API.
Agent runtimeNative Swift process runners for codex and claude, parsing their streaming JSON/event output into a common event model.
PersistenceSQLite-backed state with Swift migrations. Preserve current RemoteCode projects, chats, messages, provider threads, streaming turns, terminal snapshots, and selection where possible.

Pass Criteria

  • User can open a workspace and create terminal, browser, and Agent App surfaces in the same pane/split system.
  • Agent App can start and resume Codex and Claude threads from a selected workspace path.
  • cmux keyboard, socket, CLI, notification, and session restore primitives have planned parity or an explicit V1 deferral.
  • Current RemoteCode data model has a documented migration path.
  • Release plan covers build, signing, update, tests, and rollback.
