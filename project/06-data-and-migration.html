Data and Migration Plan

Plan to move from current RemoteCode SQLite/Bun persistence to native Swift SQLite persistence.

Storage Decision

ChoiceDecisionReason
Primary databaseSQLiteBoth current RemoteCode and cmux session state are local-first. SQLite is enough and migration-friendly.
Swift libraryGRDB preferredGood migrations, Codable support, query safety, and testability. Direct SQLite is acceptable for low-level session snapshot code.
Schema changesVersioned SQL migrationsNeed deterministic upgrades and downgrade-safe backups.
Session snapshotsSQLite plus JSON snapshot blobsStructured tables for domain data, JSON snapshot for window/pane/surface layout.

Migration Tool

remotecode2 migrate import-remotecode1 \
  --source-db /path/to/remotecode.sqlite \
  --target-db ~/Library/Application Support/RemoteCode2/remotecode2.sqlite \
  --backup-dir ~/Library/Application Support/RemoteCode2/backups
StepActionPass criteria
1Locate current RemoteCode DB or ask user to choose it.Source path is explicit in migration report.
2Copy source DB to backup directory before reading.Backup file exists and checksum is recorded.
3Run read-only schema introspection.Report source schema version or detected table set.
4Create target DB with latest migrations.Target schema version equals app schema version.
5Import projects, threads, messages, snapshots, selection.Counts match, skipped rows are listed with reasons.
6Open app into imported selected project and Agent App surface.Imported thread renders without network or provider calls.

Failure Rules

  • Never mutate the source RemoteCode database.
  • Never silently drop rows. Every skipped row must be counted and explained.
  • Provider thread IDs are sensitive enough to preserve exactly, but they are not logged in plain migration summaries unless necessary.
  • Migration can complete with warnings for missing paths, fake-provider chats, unsupported terminal snapshots, or malformed stream events.
  • Migration must be re-runnable. Existing target rows with the same source IDs update deterministically.
