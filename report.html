Decisions I took for you

Phase 0 cards (RC2-001…RC2-008) all say "decide before coding". You were asleep, so I picked safe defaults. Review each, change anything you disagree with, and update the corresponding ADR file before serious work continues.

cmux license path (RC2-001) Clean-room reimplementation. No cmux source was copied. The behavior is implemented from the planning documents only. cmux is GPL-3.0 / commercial; copying would constrain RemoteCode 2's license. Clean-room keeps your hands free. You buy a commercial cmux license — then you could lift libghostty integration, BrowserAutomation port, etc., and skip the V1 simplifications.
Layout engine (RC2-002) Custom split tree implemented in CoreModel/SplitTree.swift + Reducer.swift, rendered by NSSplitView. Bonsplit license was not validated; custom tree is small (~250 lines) and fully tested. You evaluate Bonsplit/cmux layout and want drag-to-rearrange, grouped splits, etc. — swap the reducer's renderer.
Terminal engine (RC2-003) Pipe-backed shell (Process + Pipe), not a real PTY. ANSI escapes are stripped for readability. libghostty integration requires Zig toolchain + license decision. forkpty isn't exposed via Swift's Darwin module without a C shim. Pipe-backed shell builds and runs immediately. You decide on a real terminal. Replace Sources/Surfaces/TerminalSurface.swift with a libghostty- or SwiftTerm-backed implementation. The Surface protocol won't need to change.
Provider interface (RC2-004) CLI streaming JSON. Codex uses codex exec --json, Claude uses claude --output-format stream-json --print. Auth is whatever the CLIs already have. Matches the existing RemoteCode protocol and avoids managing API keys inside RemoteCode 2. You add SDK-based runs. Implement another AgentProviderRunner conformance; the rest of the system is provider-agnostic.
V1 scope (RC2-005) Required: workspace+pane+tabs, terminal/browser/agentApp surfaces, fresh-start SQLite, JSON-RPC unix socket + CLI, direct-VPN HTTP discovery, command palette. Deferred: browser P1 (click/fill/type/wait/snapshot — return -32004), terminal copy/paste/scrollback polish, full T3 Code visual parity, pairing/device trust, Sparkle updater, signing, mobile app itself. Locked the smallest vertical slice that proves the architecture end-to-end. You promote any deferred card. The dispatcher already returns a typed not-supported error for deferred methods so promotion is incremental.
T3 Code UX spec (RC2-006/007) Not delivered. The Agent App UI ships a functional SwiftUI chat with the right structural regions (header, thread list, timeline, composer) but no T3 Code visual parity audit. I had no access to the T3 Code repo. Building a pixel-faithful clone without that source would be guesswork. You have a T3 Code checkout. Run the RC2-006 audit and feed the visual tokens into AgentAppSurface.
Mobile direct-VPN contract (RC2-008) Foundation only. DirectHTTPServer is loopback-only by default, exposes capabilities + discovery, and has zero relay/cloud-broker code. Pairing, device trust and WebSocket replay are scaffolded but not implemented. Architecture-readiness without writing the future client. Locks out relay paths so future mobile cannot accidentally introduce them. You decide which transport (Tailscale, WireGuard, raw TCP) the mobile client uses, then flesh out pairing + WS event replay.
Bundle / signing SwiftPM executable, no .app bundle. SwiftPM .executableTarget is enough to launch and test. A real .app needs Xcode project, Info.plist, entitlements, signing identity, hardened runtime, notarization. You add an Xcode project or a packaging script. Until then, do not expect Sparkle or Gatekeeper to be happy.

Things you should know to use the result safely

  • The pipe-backed terminal surface is fine for line-oriented work (git status, ls, the Codex/Claude CLIs running with --json/--print), but anything that requires a TTY (htop, vim, ncurses anything) will misbehave. Replace before relying on it.
  • swift run RemoteCode2 places state under ~/Library/Application Support/RemoteCode2Debug/. Channels are isolated; the debug, canary and stable channels never share data. Override via RC2_APP_SUPPORT, RC2_DB_PATH, RC2_CHANNEL.
  • The Unix socket lives at /tmp/RemoteCode2{Debug,Canary}.sock with mode 0600. Only your user can connect.
  • DirectHTTPServer binds 127.0.0.1:18217 by default and refuses anything else until settings.remote_access_enabled = "1". Even then, there is no auth yet — pairing/device trust (RC2-024) is unimplemented. Leave remote access off until that lands.
  • codex and claude must be in PATH for real runs. Missing binaries surface as recoverable errors with explicit "not found in PATH" messages, never silent no-ops.
  • The browser surface uses the default WKWebsiteDataStore, so cookies/profile state survive restart. Profile management (RC2-041) is not yet implemented.
  • Session restore reads the latest session_snapshots row on launch. Closing the window or quitting writes a new snapshot. Resume of active agent runs is intentionally not wired — runs that were active during a crash get marked interrupted, never reanimated.

What I would do next if I had another night

  1. Real PTY terminal. Add a small CSystem SwiftPM target that imports <util.h> so forkpty is callable; wire it into TerminalSurface, then resurrect copy/paste, resize, and selection. Track in RC2-030 + RC2-031.
  2. Pairing + device trust. Implement RC2-024: per-device tokens stored in Keychain, expiring pairing codes, rate-limited auth, audit log. Required before flipping remote_access_enabled.
  3. Command bus + event log (RC2-025). Today the dispatcher and AgentRunCoordinator emit no replayable events; the events table is empty. Add envelope writes + a WebSocket replay endpoint.
  4. T3 Code visual audit (RC2-006/094). When you have T3 Code source, port the design tokens, sidebar density, header layout, diff panel, terminal drawer. The structural slots in AgentAppSurface are ready for them.
  5. Browser P1 (click/fill/type/wait/snapshot). Add a WKUserContentController-based DOM serializer and stable element refs. The dispatcher already routes them; just unblock the handlers.
  6. Xcode project + signing. Wrap the SwiftPM modules in an .app target, add Info.plist + entitlements + hardened runtime, set up Sparkle. Required for Phase 9.
  7. Conformance isolation cleanup. AppCommandRouter uses @preconcurrency CommandRouting to bridge the main actor across an actor-isolated protocol. The proper fix is to make CommandRouting itself @MainActor or async; revisit once strict concurrency is on.
